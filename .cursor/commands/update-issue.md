# GitHub Issue に会話内容を反映

このコマンドは、**直近のCursor（Claude）との会話内容を自動的に要約・整形して、指定されたGitHub issueに追記**します。

## 使い方

```bash
/update-issue <issue番号>
```

例:
```bash
/update-issue 43
```

## 動作概要

1. **会話履歴の参照**: コマンド実行前の直近の会話内容を参照
2. **内容の抽出・要約**: 議論された内容、決定事項、追加情報などを抽出
3. **既存スタイルに合わせた整形**: 既存のissue本文のスタイルを分析し、自然に馴染む形で整形
4. **issue更新**: 既存のissue本文に追記して更新

## 実行内容

### 1. issue情報の取得

```bash
gh issue view <issue番号> --json title,body,state
```

- issueのタイトル、現在の本文、ステータスを取得
- 存在しない場合はエラーを通知

### 2. 会話内容の分析

直近の会話履歴から以下の情報を抽出：

- **議論された内容**: 技術的な議論、設計決定
- **追加の仕様**: 新たに決まった要件や仕様
- **実装の詳細**: 実装方針、コード例
- **決定事項**: 確定した内容
- **TODO項目**: 新たに発生したタスク
- **参考情報**: リンク、ドキュメント

### 3. 追記内容の生成

**重要**: 既存のissue本文のスタイルを分析し、そのスタイルに合わせて追記内容を生成します。

- 既存の見出しレベル（#, ##, ###）に合わせる
- 既存のセクション構成を踏襲
- 箇条書きのスタイル（-, *, 番号付き）を統一
- 既存の文章トーンに合わせる

会話内容を**既存のissue本文に自然に馴染む形**で整形します。特定のフォーマットを強制せず、既存のスタイルを尊重します。

### 4. issue本文の更新

既存の本文に追記内容を追加：

```bash
gh issue edit <issue番号> --body "[既存の本文]\n\n[追記内容]"
```

### 5. 更新結果の報告

- ✅ 更新成功のメッセージ
- 🔗 issueのURL
- 📝 追記された内容のサマリー

## エラーハンドリング

- **引数なし**: 「エラー: issue番号を指定してください。使い方: /update-issue <番号>」
- **無効なissue**: 「エラー: issue #<番号> が見つかりません」
- **会話内容なし**: 「エラー: 追記する会話内容が見つかりません」
- **gh CLIエラー**: 「エラー: GitHub CLIの実行に失敗しました」

## 注意事項

- 会話内容は**自動的に要約・整形**されます
- **既存のissue本文のスタイルに合わせて**追記されます（独自の見出しフォーマットは付けません）
- issueの本文は**追記**されます（置き換えではない）
- タイトル、ラベル、アサインなどは変更されません
- **コマンド実行後、確認なしで自動的に更新**されます

## 実装指示（Claude向け）

このコマンドが実行されたときの動作：

### ステップ1: 引数チェック

```typescript
// issue番号の検証
if (!issueNumber) {
  throw new Error('issue番号を指定してください。使い方: /update-issue <番号>');
}
if (!/^\d+$/.test(issueNumber)) {
  throw new Error('無効なissue番号です。数字を指定してください。');
}
```

### ステップ2: issue情報の取得

```bash
gh issue view <issue番号> --json title,body,state,number
```

取得できた情報を表示：
```
📋 Issue #<番号>: <タイトル>
状態: <OPEN/CLOSED>

現在の本文の文字数: <文字数>
```

### ステップ3: 既存issue本文のスタイル分析

**重要**: 既存のissue本文を分析して、そのスタイルに合わせて追記を生成します。

1. **見出しレベルの分析**
   - 使用されている見出しレベル（#, ##, ###）
   - 見出しの命名規則
   - 既存のセクション構造

2. **箇条書きスタイルの分析**
   - 使用されている箇条書き記号（-, *, 1.）
   - インデントのスタイル
   - チェックボックスの使用有無

3. **文章トーンの分析**
   - フォーマル/カジュアル
   - 敬体/常体
   - 絵文字の使用有無

4. **セクション構成の把握**
   - 既存のセクション（概要、背景、仕様、など）
   - セクションの順序
   - 各セクションの役割

### ステップ4: 会話履歴の分析と抽出

コマンド実行**前**の会話履歴を参照して、以下を抽出：

1. **直近の会話内容** (最新5-10メッセージ程度)
2. **技術的な議論**
   - 設計決定の理由
   - 技術選択の根拠
   - トレードオフの議論
3. **新たな要件・仕様**
   - 追加された機能要件
   - 制約条件
   - エッジケース
4. **実装の詳細**
   - 実装方針
   - コード例
   - ファイル構成
5. **決定事項**
   - 確定した内容
   - 合意事項
6. **TODO**
   - 新たに発生したタスク
   - 残作業

### ステップ5: 追記内容の生成

抽出した情報を**既存のissue本文のスタイルに合わせて**整形：

**例1: 既存のissueが「## 概要」「## 背景」「## 仕様」などのセクションを持つ場合**

→ 既存のセクションに追記、または同じスタイルで新しいセクションを追加

```markdown
## 追加の検討事項

[会話で議論された内容を自然な文章で]

## 追加の仕様

- [新たに決まった仕様1]
- [新たに決まった仕様2]

## 実装の補足

[実装方針の説明]

\`\`\`typescript
// コード例
\`\`\`
```

**例2: 既存のissueがシンプルな構造の場合**

→ シンプルに追記

```markdown
[既存の本文]

[会話で議論された内容を自然に追記]

追加で決定した事項：
- [決定事項1]
- [決定事項2]
```

**重要な原則**:
- ❌ 固定のフォーマット（「## YYYY-MM-DD 追加情報」など）を強制しない
- ✅ 既存のissueの構造とスタイルを尊重する
- ✅ 自然な形で情報を追加する
- ✅ 追記部分が既存の本文と違和感なく馴染むようにする

### ステップ6: issue更新の実行

生成した追記内容をそのままissueに追加：

```bash
gh issue edit <issue番号> --body "$(cat <<'EOF'
<既存の本文>

<追記内容>
EOF
)"
```
