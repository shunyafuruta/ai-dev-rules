# Resume

前回のセッションから作業を再開します。

コンテキストリミットで中断した場合や、新しいセッションを開始した場合に使用します。

## 実行内容

1. 状態ファイルを読み込んで現在の状況を把握
2. 決裁待ち事項を確認
3. 実装可能なタスクを特定
4. 作業を再開

## 手順

### 1. 状態ファイルの読み込み

以下のファイルを読み込んで現在の状況を把握：

- `state/current-task.md` - 現在のタスクと進捗
- `state/backlog.md` - 未着手タスク
- `state/decisions.md` - 決裁待ち事項
- `state/review-queue.md` - レビュー待ち
- `state/daily-standup/` - 最新の1on1記録

### 2. 現在の状況を確認

#### 担当者の確認

`state/current-task.md` の「担当」フィールドを確認：
- PM → タスク分解・指示出し
- Coder → 実装
- Reviewer → レビュー

#### ステータスの確認

- 待機中 → 新しいタスクをアサイン
- 進行中 → 続きから実装
- ブロック中 → ブロッカーを解消

### 3. 決裁待ち事項の確認

`state/decisions.md` を確認：

```markdown
## 決裁待ち

| ID | 事項 | 部長の判断 |
|----|------|-----------|
| DEC-001 | 認証方式 | （未回答） |
| DEC-002 | DB選定 | PostgreSQL に決定 ✅ |
```

**対応:**
- 未回答の決裁 → 影響しない部分を先に実装
- 回答済みの決裁 → その内容を反映して実装

### 4. 実装可能なタスクの特定

`state/current-task.md` の「次のアクション」を確認：

```markdown
### 次のアクション

1. ✅ ユーザー登録画面（決裁不要）→ 実装済み
2. ⏸️ 認証ロジック（DEC-001 待ち）→ スキップ
3. ▶️ プロフィール画面（決裁不要）→ これを実装
```

### 5. 作業再開

実装可能なタスクから順に実装を開始。


## 使用例

### ケース1: コンテキストリミットで中断

**セッション1:**
```
Coder: ユーザー登録画面を実装中...
Coder: （コンテキストリミット到達）
Coder: 進捗を state/current-task.md に保存して一旦終了します
```

**セッション2（新しいセッション）:**
```
User: /resume
Coder: セッションを再開します
Coder: state/ を読み込んで状況を把握...
Coder: ユーザー登録画面は完了していますね
Coder: 次はプロフィール画面を実装します
```

### ケース2: 決裁待ちで中断

**セッション1:**
```
PM: 認証方式を決定する必要があります
PM: state/decisions.md に DEC-001 を記録
PM: 決裁待ち中に実装可能な部分（プロフィール画面）を先に実装します
Coder: プロフィール画面を実装中...
```

**セッション2（決裁後）:**
```
User: /resume
PM: state/decisions.md を確認...
PM: DEC-001 に回答がありました！JWT に決定
Coder: 認証ロジックを JWT で実装します
```

### ケース3: 毎朝の作業再開

```
User: /resume
PM: おはようございます！昨日の続きから再開します
PM: state/daily-standup/2024-02-06.md を確認...
PM: 昨日はユーザー登録機能の80%まで完了
PM: 今日はテストとレビュー依頼を進めましょう
```

## 注意事項

### 状態ファイルの更新を徹底

セッション終了時に必ず以下を更新：
- `state/current-task.md` - 進捗を記録
- `state/backlog.md` - 完了タスクを移動
- `state/decisions.md` - 決裁事項を記録

### コンテキストリミット警告

コンテキストが90%に達したら：
1. 現在の進捗を `state/current-task.md` に保存
2. 「コンテキストリミットに近づいています。一旦終了します」と通知
3. 次のセッションで `/resume` を使用

### 決裁待ちの明確化

決裁待ちタスクには必ず以下を記載：
- 決裁ID（DEC-XXX）
- 影響範囲
- 決裁待ち中に実装可能な部分

## 自動保存

長時間のセッションでは、定期的に状態を保存：
- 30分ごとに `state/current-task.md` を更新
- タスク完了時に `state/backlog.md` を更新
- 決裁事項発生時に `state/decisions.md` を更新
