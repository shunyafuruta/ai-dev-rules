# Daily Standup

階層型AI開発チームの日次スタンドアップ（1on1）を実施します。

## 実行内容

1. 今日の日付のスタンドアップファイルを作成
2. テンプレートから質問を生成
3. 各ロール（部長↔PM、PM↔Coder、PM↔Reviewer）の進捗を確認
4. ブロッカーや改善提案を収集
5. 明日のアクションアイテムを決定
6. メトリクスを更新

## 手順

### 1. 今日の日付のファイルを作成

```bash
# state/daily-standup/YYYY-MM-DD.md を作成
今日の日付: {{TODAY}}
```

テンプレート: `state/daily-standup/template.md` を使用

### 2. 各ロールとの1on1を実施

#### 部長（人間）↔ PM（AI）

以下を確認：
- 完了したこと
- 進行中のこと
- ブロッカー・相談事項
- 改善提案

**質問例:**
```
部長さん、昨日からの進捗はいかがですか？
- 完了したタスクや決定事項はありますか？
- 現在進行中のタスクで気になることはありますか？
- ブロックされていることや相談したいことはありますか？
- チームの動き方で改善したい点はありますか？
```

#### PM（AI）↔ Coder（AI）

`state/current-task.md` と `state/backlog.md` を確認して：
- 完了したタスク
- 進行中のタスク
- ブロッカー
- 技術的な学び・発見

#### PM（AI）↔ Reviewer（AI）

`state/review-queue.md` を確認して：
- レビュー完了件数
- 指摘事項のパターン
- 品質に関する気づき
- 改善提案

### 3. メトリクスを記録

以下を記録：
- タスク完了数
- レビュー承認/差し戻し数
- 時間の見積もりと実績

### 4. 明日のアクションアイテムを決定

ブロッカーや改善提案から、明日やるべきことを1-3個リストアップ

### 5. 前回からの改善進捗を確認

`state/improvements/improvement-log.md` を参照して、実施中の改善アクションの進捗を確認

## 出力

`state/daily-standup/{{TODAY}}.md` に記録

## 注意事項

- 毎日同じ時間に実施することを推奨（例: 朝9時）
- 15-30分以内に完了することを目標に
- ブロッカーは必ず明確にして、解決策を検討
- 改善提案はすぐに実施するか、`state/improvements/improvement-log.md` に記録

## 例

```markdown
# 2024-02-07 Daily Standup

## 🎯 部長（人間）↔ PM（AI）

### 完了したこと
- ログイン機能の要件定義を承認
- Issue #123 を作成

### 進行中
- ダッシュボード機能の検討

### ブロッカー・相談事項
- なし

### 改善提案
- タスクの粒度をもう少し細かくしたい

### 部長からのフィードバック
- タスク粒度については賛成、次のタスクから反映してください

---

## 📋 PM（AI）↔ Coder（AI）

### 完了したタスク
- ログイン画面の実装
- 入力バリデーションの実装

### 進行中のタスク
- ユニットテストの作成（60%完了）

### ブロッカー
- なし

### 技術的な学び・発見
- Zodでのバリデーションが想像以上に便利だった
- React Hook Formとの組み合わせで型安全に実装できた

### PMからのフィードバック
- 良いペースです。テストは明日中に完了できそうですか？

---

## 🔍 PM（AI）↔ Reviewer（AI）

### レビュー完了件数
- 承認: 2件
- 差し戻し: 1件

### 指摘事項のパターン
- エラーハンドリングの漏れ（1件）
- 型定義の不足（1件）

### 品質に関する気づき
- 全体的にコード品質は向上している
- ただしエラーケースの考慮が甘い傾向

### 改善提案
- エラーハンドリングのチェックリストを作成したい

### PMからのフィードバック
- チェックリスト作成は良いアイデアです。次のレトロスペクティブで議論しましょう

---

## 📊 本日のメトリクス

### タスク
- 完了: 2件
- 進行中: 1件
- ブロック中: 0件

### レビュー
- 承認: 2件
- 差し戻し: 1件
- 差し戻し率: 33%

### 時間
- 見積もり: 6h
- 実績: 5.5h
- 差分: -0.5h

---

## 💡 明日のアクションアイテム

1. ユニットテストを完了する
2. エラーハンドリングのチェックリスト案を作成
3. ダッシュボード機能の要件を整理

---

## 🔄 前回からの改善進捗

| 改善項目 | ステータス | 効果 |
|---------|-----------|------|
| タスク粒度の最適化 | 実施中 | リードタイムが3日→2日に短縮 |
```

## タスク後の行動

1. ブロッカーがあれば即座に対処
2. 改善提案を `state/improvements/improvement-log.md` に追記
3. メトリクスを `state/metrics/team-metrics.md` に反映
4. 明日のアクションアイテムを `state/current-task.md` に追加
